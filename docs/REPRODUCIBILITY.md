# 复现范围与环境

本发布版本为v3.0.0。历史实验的训练/寻优核、参数文件、CSV、精确请求/R响应与21版模型均被固定。元数据里的私人服务器路径已脱敏；`ORIGIN.json`保存脱敏前部分元数据的哈希及原始运行源码标识。发布源码的入口增加了跨平台CLI及外接评分器适配，这些不被描述为原始服务器代码逐字相同。

## 三种不同含义

1. `run.py reproduce`：从保存的精确配对重新核对本次真实R和最佳点，不调用评分器、不训练。结果来源标为`archived_real_evaluation`。
2. `run.py train` / `run.py replay`：按固定配置重新训练。replay固定已保存的候选/真实R序列，每版只用当时可见的数据；报告固定探针预测相对归档模型的差异。这不证明重新生成的候选轨迹完全一致。
3. `run.py online`：从原始2048行冷启动开始，由新的外接评分器对新候选给出真实R，独立执行20×50。评分器需用户提供。本发布过程没有开启新的真实评估实验。

新候选的预测绝不直接继承“附近旧点”的真实R。`optimize`的输出标为预测，没有真实R。最终历史推荐只取已经真实评估过的最优点。

## 环境

CPU参考：Python3.10.21、NumPy1.26.4、Torch2.6.0、float64、单线程、固定数据顺序与种子。依赖由带哈希的三个平台wheel锁文件和公共锁文件固定。bootstrap支持Windows/Linux x86-64及macOS arm64；首次安装可能下载Python和依赖，已有环境后无需联网。

历史实验：Linux、Torch2.6.0+cu118、共享A100物理GPU2、2GiB PyTorch显存预算；逆向后端为单独Python3.11环境，8个CPU评估工作进程。共享卡的其他任务会影响耗时，不能用单次耗时推导稳定加速倍数。

CPU/GPU和不同操作系统的数值库可以产生差异。项目要求结构、数据来源、约束和计算行为保真；不承诺参数逐位相同，也不承诺新的在线运行必然等于104.140308。重训时实际测量并输出预测差异。

发布前验证记录在`VALIDATION.json`；Windows提供启动脚本和依赖锁，但尚未完成真实Windows电脑上的全量训练验收。请以实际测得的兼容性记录为准。

## 文件与恢复

`MANIFEST.json`固定可发布文件的SHA256；运行产物应写到忽略的`outputs/`、`sessions/`。修改源码或数据后完整性核验会失败；开发衍生版本应独立更新版本和清单。

在线正式运行在项目根目录建立`formal-budget.json`，锁定一个session，保留最多20次调用。输入与预算在启动评分器前落盘；成功返回的pending结果可恢复且不重复加入反馈；状态不确定的失败停止，不能自动重发。`--resume`时配置和源码必须匹配。

原实验的全部逐小时轨迹和完整服务器归档另行保存，没有纳入这个便于同学下载的公开源码仓库；公开仓库保留全部1000组标量真实反馈和模型训练资料。评分来源、设备状态和耗时记录属于历史证据，不是新运行的默认机器路径。

## v3的历史策略核验

公开包保存了每批评分前的原始/锚定预测、可见训练行数、实际候选、真实响应与阶段门槛。测试按20个历史批次依序重算精修触发和去偏启停，不允许用当前或未来批次标签提前选点。前16轮请求哈希与v1对应轮次相同，参考哈希记录于ORIGIN.json。

在线程序默认从原始2048行从头训练；离线replay固定历史输入/R配对，仍不把历史分数赋给重新生成的候选。optimize会从所选历史轮次恢复当时可用的阶段和去偏状态，仅生成未评分提案。
