# 复现范围与环境

本发布版本为v4.0.2，归档实验版本为v4.0.0。历史实验的训练/寻优核、参数文件、CSV、精确请求/R响应与21版模型均被固定。元数据里的私人服务器路径已脱敏；`ORIGIN.json`保存脱敏前部分元数据的哈希及原始运行源码标识。发布源码的入口增加了跨平台CLI及外接评分器适配，这些不被描述为原始服务器代码逐字相同。

## 三种不同含义

1. `run.py reproduce`：从保存的精确配对重新核对本次真实R和最佳点，不调用评分器、不训练。结果来源标为`archived_real_evaluation`。
2. `run.py train` / `run.py replay`：按固定配置重新训练。replay固定已保存的候选/真实R序列，每版只用当时可见的数据；报告固定探针预测相对归档模型的差异。这不证明重新生成的候选轨迹完全一致。
3. `run.py online`：从原始2048行冷启动开始，由新的外接评分器对新候选给出真实R，独立执行20×50。评分器需用户提供。本发布过程没有开启新的真实评估实验。

新候选的预测绝不直接继承“附近旧点”的真实R。`optimize`的输出标为预测，没有真实R。最终历史推荐只取已经真实评估过的最优点。

## 环境

CPU参考：Python3.10.21、NumPy1.26.4、Torch2.6.0、float64、单线程、固定数据顺序与种子。依赖由带哈希的三个平台wheel锁文件和公共锁文件固定。bootstrap支持Windows/Linux x86-64及macOS arm64；首次安装可能下载Python和依赖，已有环境后无需联网。

历史实验：Linux、Torch2.6.0+cu118、共享A100、2GiB PyTorch显存预算；逆向后端为单独Python3.11环境，8个CPU评估工作进程。共享卡的其他任务会影响耗时，不能用单次耗时推导稳定加速倍数。

CPU/GPU和不同操作系统的数值库可以产生差异。项目要求结构、数据来源、约束和计算行为保真；不承诺参数逐位相同，也不承诺新的在线运行必然等于103.856997。重训时实际测量并输出预测差异。

发布前验证记录在`VALIDATION.json`；Windows提供启动脚本和依赖锁，但尚未完成真实Windows电脑上的全量训练验收。请以实际测得的兼容性记录为准。

## 文件与恢复

`MANIFEST.json`固定可发布文件的SHA256；运行产物应写到忽略的`outputs/`、`sessions/`。修改源码或数据后完整性核验会失败；开发衍生版本应独立更新版本和清单。

在线正式运行在项目根目录建立`formal-budget.json`，锁定一个session，保留最多20次调用。输入与预算在启动评分器前落盘；成功返回的pending结果可恢复且不重复加入反馈；状态不确定的失败停止，不能自动重发。`--resume`时配置和源码必须匹配。

原实验的全部逐小时轨迹和完整服务器归档另行保存，没有纳入这个便于同学下载的公开源码仓库；公开仓库保留全部1000组标量真实反馈和模型训练资料。评分来源、设备状态和耗时记录属于历史证据，不是新运行的默认机器路径。

## v4的历史策略核验

核验20批配对、710/290角色配额、成对比较完整性、边界区间只引用既有真实反馈、诊断模型排除组，以及精修/去偏门槛的逐轮因果重放。本次未触发精修、未启用去偏。原始评分后端不公开，但最优点的8周三楼及全区净负荷输出已经公开，`reproduce`可独立重算最终R。

在线程序默认从原始2048行从头训练；离线replay固定历史输入/R配对。optimize仅生成未评分提案；在反馈20轮之后复用第20轮的50/0角色策略，不提交第21次评估。

## v4.0.2确定性补丁

默认运行入口在导入数值库前强制固定线程、Python哈希种子2026和UTF-8；哈希/编码需要时启动一个相同参数的新解释器。库调用者若直接import，应在启动解释器前设置环境，正式验收使用run.py。Python、NumPy、Torch全局随机数及每模型作业均重置；原模型和候选生成器的局部种子保持不变。

禁用TF32、cuDNN、MKLDNN与可选einsum路径优化，显式选择非foreach、非fused的Adam实现，使用稳定投影排序。此补丁可能改变相对旧GPU实现的数值轨迹，不将归档R视为新实现已重获的成绩。保留v4.0.0标签及原base.py快照，ORIGIN.json明确记录修改。归档模型、标签及最优参数不变。

check-determinism导出数值数组签名并比较内容；不比较带时间戳的NPZ压缩文件哈希或运行耗时。两个新进程各使用完整2048行、五种子各3轮、两阶段各8步寻优，覆盖训练、预测、学习候选及候选去重。--epochs和--search-steps可扩大检查预算，仍不调用评分器。默认检查属于短流程检查，不证明全20轮或跨系统效果一致。

跨电脑可将一台的outputs/determinism/run-1-signature.npz复制到另一台，在check-determinism中加--reference路径，查看模型状态、探针预测、候选和候选预测的最大绝对差。算法会如实报告差异，不将“固定设置”解释为跨系统逐位保证。Windows全量训练仍待实际验收。

发布前Mac和Linux各29项测试通过。两平台各自两次独立进程的短流程数值数组完全一致；Mac与Linux的探针及候选预测最大绝对差5.684341886080802e-14，候选权重差2.220446049250313e-16。范围为全部2048行、五模型各3轮和每阶段8步寻优，不能外推为完整20轮保证。具体记录与参考签名在validation/。Git在core.autocrlf=true时的原字节检出检查通过。Windows自动检查与报告见GitHub Actions，Windows全量训练仍未验收。

v4.0.2进一步要求训练解释器精确为Python3.10.21（仅复核归档仍可使用其他兼容Python）。Windows/Linux自动检查调用与交付相同的bootstrap.py创建固定环境，避免系统自带Python小版本差异。v4.0.1的Windows兼容性检查实际用3.10.11，其记录另行保留，不冒充固定环境验收。
